# 회고 — 유휴 시 렌더 중단 + 탭 전환 시 뷰어 상태 보존

- 작업: `viewer-idle-and-state-persistence` (task 7)
- 일자: 2026-08-22
- 결과: `verified: yes` — 유닛 58→79, e2e 15→21, 통합 11 유지, vsix 2.43 MB

## 계획 대비 발산

**1. dirty 신호 설계가 교착을 만들었다 (사용자 가시 버그).**
계획은 `camera.onViewMatrixChangedObservable` 을 wake 소스로 지정하고, "렌더 루프를 멈추지 않으니
wake 소스를 놓쳐도 카메라를 건드리면 다음 프레임에 자동 복구된다"는 **근거까지 적었다.**
그 근거가 틀렸다 — `ArcRotateCamera` 는 `scene.render()` 안에서 입력을 처리하므로, 그리지 않으면
입력을 읽지 않는다. 유휴 진입 후 드래그하면 화면이 얼어붙었다. 캔버스 DOM 입력 이벤트를 wake
소스로 추가해 해결.

**2. 저장 디바운스가 Inspector 켠 동안 영원히 밀렸다.**
저장 트리거를 `onAfterRenderObservable` 에 걸고 400ms 디바운스했더니, 연속 렌더링 중에는 타이머가
계속 리셋돼 저장이 일어나지 않았다. 최대 대기 2초 + `pagehide`/`visibilitychange` 즉시 flush 로 해결.

목표·비목표·슬라이스 7개는 전부 계획대로 착지했다. 드롭된 슬라이스도, 침범한 비목표도 없다.
발산은 둘 다 슬라이스 **안에서의** 기술적 정정이었고 런 중에 고쳐졌다 — 그래서 재그릴링 대상이
남지 않았다고 판단했다.

## 깨진 전제 — 하나이고, 패턴이 있다

그릴링 중 Babylon/VS Code 사실을 **네 번 실측했다**: 프리뷰 탭 동작 · 배경 웹뷰 생존 ·
`resolveCustomEditor` 호출 횟수 · `setState` 생존. 넷 다 맞았고, 그중 둘은 **내 추천을 뒤집었다**
(동시 뷰어 상한은 무가치, 리터럴 요구는 이미 충족).

**재지 않고 추론한 항목은 딱 하나였다 — 입력 처리가 어디서 일어나는가. 그리고 그게 유일하게 깨졌다.**

이건 "Babylon 을 조심하라"가 아니라 더 좁은 교훈이다.

## 다음에 다르게 할 것

1. **계획이 Babylon 동작을 근거로 삼을 때는 그릴링 중에 재고, 잰 값을 계획에 적는다.**
   이번 계획의 다른 근거에는 전부 실측값이 붙어 있었고 전부 맞았다. 붙지 않은 하나가 틀렸다.
   추론이 싸 보일 때가 정확히 위험한 지점이다.
2. **렌더링·입력 타이밍을 바꾸는 변경에는 실제 입력을 구동하는 e2e 를 필수로 둔다.**
   이번엔 있었고 얼어붙는 버그를 잡았다. **유닛 테스트 8개는 전혀 보지 못했다** — 게이트 로직은
   옳았고 배선이 틀렸기 때문이다. (이미 코드로 굳었으므로 별도 문서화는 하지 않았다.)
3. **e2e 의 콘솔 캡처를 상설화한다.** 이번에 넣었다. 파트 4/4 의 "콘솔을 먼저 읽었으면 30분을
   아꼈다"를 회귀 장치로 만든 것이다. (ADR 로 승급했다.)

## 잘 된 것

- **실측이 그릴링의 결론을 두 번 뒤집었다.** 사용자의 리터럴 요구("한 탭에 열기")가 이미 충족돼
  있었고, 내가 추천한 "동시 뷰어 상한"은 값이 없었다. 재보지 않았으면 무의미한 기능을 만들었다.
- **요구가 만든 부작용을 함께 찾아냈다.** 리소스 절약 설정 때문에 탭 전환만으로 측정이 사라지던
  것 — 파트 4/4 는 "탭을 **닫으면**" 사라진다고 잘못 기록했다. 요청 범위 밖이었지만 같은 원인이었다.
- **TDD 가 깨진 입력 방어를 실제로 설계하게 만들었다.** `viewerState` 의 13개 테스트 중 10개가
  방어 케이스다. 테스트를 먼저 쓰지 않았다면 "정상 경로만 동작하는 복원"을 만들었을 것이다.

## 남은 공백 (의도적)

실제 VS Code 에서 우리 상태 payload 가 왕복하는 것은 한 줄로 단정하지 못했다. 확장 호스트
테스트는 웹뷰 내부를 읽을 수 없다. 3겹 논거(VS Code 의 `setState` 생존 실측 + payload 왕복 유닛
테스트 + 셰임 기반 e2e 복원)로 대체했다. 닫으려면 테스트를 위해 제품 표면을 추가해야 해서
대가가 크다고 판단했다.
