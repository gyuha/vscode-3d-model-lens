**없다.** 목표·비목표 6건·슬라이스 1개가 모두 계획대로 착지했다. 침범한 비목표도 없다 —
치수의 `axis` 단수 8곳은 그대로 살아 있고, `VIEWER_STATE_VERSION` 은 1 이며, `extentDiagonal`
함수는 `measurement.ts`·`viewer.ts` 를 위해 남아 있고(`chrome.ts` 의 import 목록에서만 빠졌다),
`Chrome` 클래스 이름은 유지한 채 doc 주석만 사실에 맞게 고쳤다. README·`package.json` 은
손대지 않았다.

**계획 단계에서 이미 잡아 둔 함정이 실제로 함정이었음을 확인했다.** DoD 4 의 부정 검사를
`grep -rniE 'axesviewer|\baxes\b'` 로 적었다면 `setAxesVisible`(`chrome.ts:31` · `main.ts:136`)을
단어 경계 때문에 놓쳐, **삭제가 두 곳 남았는데도 검사가 0 을 내는 fail-open** 이 됐다. 계획을
쓰면서 패턴을 두 그룹으로 실행해 대조한 것이 그것을 잡았다 — 직전 작업의 회고가 지적한
"계획 시점에 명령을 한 번 실행해 본다"가 이번에는 실제로 값을 냈다.

## 계획 밖에서 한 검증 하나 (삭제한 일회성 검사)

계획의 유일한 되돌리기 어려운 결정 — **버전을 올리지 않아 기존 저장 상태가 살아남는다** — 은
기존 스위트가 덮지 않는다. 기존 e2e 의 복원 테스트(`reload 후 측정·카메라·토글·측정 모드가
복원된다`)는 **새 코드가 쓰고 새 코드가 읽는** 왕복만 단정하기 때문이다. 그래서 `axes: true` 키가
남은 version 1 상태를 넣어 복원시키는 **임시 테스트를 한 번 돌려** 측정 1건·카메라 `radius: 42`·
토글 3키가 그대로 복원되고 `axes` 는 스키마에서 사라졌음을 확인한 뒤 **파일을 삭제했다**
(삭제 후 `grep -rni axes src/ test/` 재확인 0). 제품 코드에 남기지 않은 이유는 계획이 순수 삭제
작업이고, 이 단정을 상설화하려면 "구 스키마"라는 개념을 테스트에 도입해야 해서다 — 그건 별개
판단이다.

## 남은 공백 (의도적)

**기즈모가 화면에서 사라졌다는 것을 픽셀로 단정하지 않았다.** 패널의 `Axes` 행 부재는 DoD 4 가
`webviewHtml.ts` 원본에서 직접 확인하므로 전이적으로 덮이지만, 3D 기즈모의 시각적 부재는
"`AxesViewer` 를 아무도 생성하지 않는다"는 코드 수준 확실성(DoD 4 + tsc)으로 갈음했다.
그리기 대상 노드가 존재하지 않으므로 렌더될 수 없다.

**픽 회귀는 6개 e2e 가 지킨다.** `makeUnpickable` 제거의 유일한 실질 위험이 픽 간섭이었으므로,
`정점 스냅으로 찍은 모서리 길이가 기대값과 일치한다` · `드래그는 측정을 만들지 않는다` ·
`Inspector 를 켠 상태에서도 측정할 수 있다` 등 측정·스냅 e2e 6건이 통과하는 것을 증거로 삼았다.
