# 뷰어 배경은 3상태 enum 하나로 소유하고, 라이트는 순백이다

뷰어 배경을 사용자가 고를 수 있게 하면서 두 가지를 함께 결정했다.

**설정은 하나다.** 기존 `modelLens.backgroundColor`(임의 색 문자열, 비우면 테마 따름)를 제거하고
`modelLens.background`(`theme` | `light` | `dark`) 하나로 교체한다. 같은 것을 다투는 설정이 둘이면
사용자는 "왜 토글이 안 먹히지"를 겪는다. 임의 색 지정은 함께 사라진다 — 이 확장의 목적은 치수
측정이지 커스터마이징이 아니고, 수요가 확인된 적이 없다. 0.0.1 미게시 시점이라 지금이 지울 수
있는 유일한 때였다. enum 이라 VS Code 설정 UI 가 드롭다운이 되고 뷰어 패널의 드롭다운과 1:1 로
대응한다. 나중에 임의 색이 필요해지면 enum 에 `#rrggbb` 를 섞는 것은 하위 호환으로 가능하다.

**`light` 는 `#ffffff` 다 — 밝은 회색이 아니다.** "3D 뷰어는 순백보다 밝은 회색이 낫다"는 통념이
있고, 이 프로젝트에서는 그것이 **틀렸다**. 기본 머티리얼(`chrome.ts` 의 `baseColor(0.78,0.78,0.8)`)이
이미 밝은 회색이라, 배경을 회색으로 낮출수록 모델과 가까워진다. `cube.stl`(가장 불리한 케이스 —
무광 회색 STL)을 실제로 렌더해 밝기 분포를 쟀다:

| 배경 | 모델 최암부 (p05) | 배경 밝기 | 대비 |
|---|---|---|---|
| `#ffffff` | 192 | 255 | **63** |
| `#f0f0f0` | 192 | 240 | 48 |
| `#e0e0e0` | 192 | 224 | 32 |
| `#1f1f1f` | 255 (최명부) | 31 | **224** |

배경을 어둡게 할수록 라이트 모드의 대비가 **떨어진다**. 그래서 순백을 쓴다. `dark` 의 `#1f1f1f` 는
VS Code Dark Modern 의 `editor.background` 와 같은 값이며, `light` 의 `#ffffff` 도 Light Modern 과
같다 — 그래서 라이트 테마 사용자에게는 `theme` 와 `light` 가 같은 결과가 되어 혼란이 없다.

이 표를 여기 박아 두는 이유는 되돌리기가 어려워서가 아니라 — 색값은 언제든 바꿀 수 있다 —
**다음 사람이 `#ffffff` 를 보고 "회색이 낫지"라며 고치려 들 것이기 때문이다.** 고치려면 먼저
다시 재라.

## Consequences

- **라이트 모드에서 무광 STL 은 대비가 약하다(63).** 어느 배경값을 골라도 그렇다. 이건 배경이
  아니라 기본 머티리얼과 조명의 문제이므로, 고치려면 `ensureMaterials` 의 색이나 윤곽선을
  손대야 한다 — 모든 모델의 외형이 바뀌는 별개의 작업이다. 알려진 한계로 남긴다.
- 그리드 색 `Color3(0.45,0.45,0.45)` 는 양쪽 배경에서 모두 대비를 유지하므로 손대지 않는다.
