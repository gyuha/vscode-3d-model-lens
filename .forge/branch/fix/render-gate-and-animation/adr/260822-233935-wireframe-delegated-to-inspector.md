# 와이어프레임은 뷰어 패널에서 빠지고 Inspector 에 위임된다

뷰어 패널의 `Wireframe` 체크박스를 제거한다. 앞으로 와이어프레임을 보려면 Babylon Inspector 를
켜고 머티리얼 속성에서 켜야 한다. `Chrome.setWireframe` 은 **호출자 없이 코드에 남는다.**

## 알고도 받아들인 대가

이 결정은 문서화된 방향을 거스른다. 그래서 무엇을 알고도 택했는지 남긴다 — 나중에 재검토할
사람이 같은 논의를 처음부터 다시 하지 않도록.

**1. Inspector 의 와이어프레임은 등가물이 아니다.** `@babylonjs/inspector` 번들을 직접 읽어
확인했다 — 스위치가 `{ label: "Wireframe", target: material, propertyKey: "wireframe" }` 로
**머티리얼 하나당 하나** 붙는다. 씬 전역 토글이 없다. 우리가 지우는 패널 토글은
`Chrome.setWireframe` 이 **모든 메시의 머티리얼에 일괄 적용**하는 것이었다. 머티리얼이 하나인
STL 은 등가지만, 머티리얼이 여러 개인 glTF/GLB 에서는 씬 탐색기에서 하나씩 골라 각각 켜야 한다.

**2. Inspector 를 켜면 유휴 렌더 중단이 무력화된다.** 추측이 아니라 이 저장소의 e2e 가 단정하는
사실이다 — `Inspector 를 켜면 연속 렌더링한다 — fps 카운터와 기즈모가 렌더 루프에 의존한다`.
즉 와이어프레임 하나를 보려고 Inspector 를 켜면 유휴 절전이 꺼지고 계속 그린다.
`260822-162443` 계열의 유휴 게이트가 그 시간 동안 아무 효과가 없다.

**3. 코드와 README 가 와이어프레임을 측정의 전제조건으로 명시했다.** `chrome.ts` 의 주석은
*"와이어프레임은 취향 기능이 아니라 정점 스냅의 전제 조건이다 — 어디에 정점이 있는지 보여야
코너에 스냅할 수 있다"* 였고, README 는 *"Turn on wireframe to see where the vertices are"* 였다.
따라서 이 결정은 **주 기능(측정)의 전제조건을 서드파티 디버그 UI 로 옮기는 것**이다.
README 문구는 이 결정에 맞게 다시 쓴다 — 낡은 안내를 남기는 것이 더 나쁘다.

**4. 용어집이 둘을 명시적으로 분리해 두었다.** `Inspector` 항목은 *"우리가 만드는 뷰어 패널과
다른 것이며, 우리 코드가 아니다"* 라고 정의한다. 이 결정은 그 경계를 그대로 두면서, 기능 하나의
접근 경로만 경계 밖으로 넘긴다.

## `setWireframe` 을 남기는 이유

패널 배선만 제거하고 `Chrome.setWireframe` · `wireframeOn` · `wireframe` 게터 ·
`meshes` 필드/매개변수는 **유지한다.** 연쇄를 끝까지 따라가면 `Chrome` 은 그리드만 든 클래스가
되고 `viewer.ts` 의 생성자 호출부도 바뀌는데, 그 되돌림 비용을 지금 치르지 않기로 했다.

**그래서 코드에는 호출자 없는 public 메서드가 남는다. 이것은 실수가 아니다.** `grep` 으로
"죽은 코드"를 찾는 다음 사람이 이 ADR 을 못 보고 지울 수 있으므로, 계획의 완료 정의에
`grep -c setWireframe src/webview/chrome.ts` → `1` **회귀 가드**를 넣어 삭제를 검사로 막는다.

## 되돌리기 전에 읽을 것

패널 토글을 되살리려면 세 곳이 함께 필요하다 — 체크박스(`webviewHtml.ts`),
배선(`main.ts` 의 `setChecked` · `bindCheckbox`), **그리고 지속성**. 저장 상태
(`TogglesState.wireframe`)는 이 결정과 함께 제거됐고 `VIEWER_STATE_VERSION` 은 1 로 남았으므로
(사용자의 측정값·카메라를 버리지 않기 위해), 되살릴 때 지속성도 새로 붙여야 한다.
`setWireframe` 만 살아 있는 것으로는 상태가 세션을 넘어 유지되지 않는다.

되살리는 것이 맞다고 판단되는 신호: 측정 사용자가 코너 스냅에서 정점을 못 찾는다는 보고,
또는 머티리얼이 여러 개인 모델에서 Inspector 경로가 실용적이지 않다는 확인.
